# 提示 A/B 归因

项目：koupi-detector（口癖检测器）。

把生成侧三组 system 放在一张表里：无额外提示、风格提示、ADHD 短提示。检测侧不写进这些 system，只在回复写完后扫描，所以不把它算成一次生成实验。

```bash
node cli.mjs prompt-ab --spec examples/prompt-ab.json
```

变量文本在 `examples/prompt-ab.json`。有落盘 `runs` 时，脚本用每千字口癖率和对照比：

- 比对照高出不少于 1 /千字：提示诱导
- 变化落在门槛内：无增益
- 比对照低出不少于 1 /千字：有下降
- 没有数字：未测

提示文本自己被检测器打中时，表上「提示文本含口癖」为是。这只说明有提示诱导的风险，不等于已经跑过生成。

本仓库没有这三组提示的生成 runs。下表是脚本对当前 spec 的输出，不是一次新的模型实验，也不沿用别处草稿里的「无增益」。

| 变量 | 位置 | 提示文本含口癖 | 每千字口癖率 | 归因 |
| --- | --- | --- | --- | --- |
| 无额外提示 | 生成侧 | 否 | — | 未测 |
| 风格提示 | 生成侧 | 否 | — | 未测 |
| ADHD 短提示 | 生成侧 | 否 | — | 未测 |

要补跑，把同一批 `examples/cross-model-prompts.json`、温度 0 的结果按 `id` 写进 spec 的 `runs`（`ticPerKilo`、`chars`），再执行上面的命令。没有密钥时不要填数字。
