# 回复前自查

项目：koupi-detector（口癖检测器）。

草稿先扫描。有判定为口癖的命中时，把命中片段、类别和规则算出的省力改写交给改写器，最多重写 2 轮，每轮后再扫。不可判定不触发改写。离线改写器在一句删完不成立时保留该句原文，标成需模型改写，并带回命中，不把词面套话硬删成残句。这份报告用离线改写器，不调用模型。句子都是虚构的。

改写器：offline。

复现：

```bash
node cli.mjs rewrite --drafts examples/selfcheck-drafts.json --report docs/selfcheck-report.md
```

含口癖指初扫至少有一处 `verdict: tic`。每千字 = 口癖处数 / 字数 × 1000，字数去掉空白、保留标点。冗余比只平均句式口癖里有断言可留的那些条，词面套话不进这个均值；改完之后没有这类命中，就写成 —。字数变化是这一组改写后字数减改写前字数。

已修复：文本改过、口癖清完、完整性为 1。需模型：初扫有口癖，但离线改写留下了原句或还没清完，命中反馈仍返回。原样通过：初扫没有口癖，文本不变。这三栏在每一组里互斥，加起来等于条数。

保真是机器算的字面 Dice，不靠人判。载荷是「命中跨度以外的字」加上「该命中的省力改写」；词面套话没有省力改写，那一截不要求留下。保真 = 2 × LCS(载荷字列, 结果字列) / 两边字数。只计汉字、数字和拉丁字母。两边都空时记 1。

这个保真看不出同义替换，也会把语序大改当成丢失。句式口癖内部的断言只通过省力改写进入载荷，改写器若换成另一个事实，分数会掉。词面套话被整段删掉时，套话里面偶有的具体词不在载荷里，删掉仍可能是满分。它也不检查改写后好不好读，所以口癖清了、句子塌了，保真仍可以是 1.000。

需模型的条目保留原句，词面套话还在正文里。保真的载荷不含这截套话，多出来的字会把 Dice 拉低。因此这一组的平均保真可以低于 1，同时完整性仍是 1.000。硬删成残句时则相反：保真可以是 1.000，完整性是 0。

完整性是另一项机器指标，和保真并列。按。！？切开，完整性 = 成立的句数 / 句数。一句记不成立的情况：去掉标点后不足 3 个字；某个逗号分句只剩「一样」「似的」或「一般」；整句收在「显得、像在、像是、仿佛、好像」上；整句收在「得」上，且不是「值得、舍得、懂得、获得、赢得、记得、认得」这类词；出现「一个的」「一件的」这种量词紧贴「的」。空文本记 0。这批草稿的原文都成立，表里的平均完整性是改写后的。

完整性的局限：正当的「一个人的伞」会被「一个的」误伤；短于 3 个字的完整短句也会被算残。它不判断好不好读，只拦这几类删完之后明显站不住的句子。

## 接上模型

默认 `--rewriter offline`，句式口癖换成省力改写。词面套话只有在删完这一句仍然成立时才删；否则保留原句，标成需模型改写，并返回命中。不需要密钥。

`--rewriter llm` 调用 OpenAI 兼容的 `POST {KOUPI_LLM_BASE_URL}/chat/completions`。密钥只读环境变量，不写进仓库。

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `KOUPI_LLM_API_KEY` | 必填，否则 llm 模式直接失败 | 无 |
| `KOUPI_LLM_BASE_URL` | 接口根路径，后面会接 `/chat/completions` | `https://api.openai.com/v1` |
| `KOUPI_LLM_MODEL` | 模型名 | `gpt-4o-mini` |

DeepSeek 示例：`KOUPI_LLM_BASE_URL=https://api.deepseek.com/v1`，`KOUPI_LLM_MODEL=deepseek-chat`，再设 `KOUPI_LLM_API_KEY`。温度固定为 0。模型只改列出的那一截命中，未列出的字用原文拼回；已有省力改写的直接套用，不调模型。不拿到评测分组。

## 单条用法

```bash
node cli.mjs rewrite examples/selfcheck-one.txt
node cli.mjs rewrite - --json <<'EOF'
他没有生气，也没有惊讶，只是看着她。
EOF
```

MCP 工具名是 `tic_rewrite`。`rewriter` 默认 `offline`，`maxRounds` 默认 2 且不超过 2。可选 `before`，表示这条回复之前的对话。
