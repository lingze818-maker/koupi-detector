# 数据闭环

项目：koupi-detector（口癖检测器）。

从金标和共识 tic 的虚构句导出两份文件。不调用模型。不改检测判定。共识句只收正文，不收场景前文。

```bash
node cli.mjs data --gold examples/gold.json --consensus examples/consensus-tic.json
```

写出 `data/preference.jsonl` 和 `data/sft.jsonl`。

## 从哪来

| 来源 | 条数 | 用什么 |
| --- | --- | --- |
| `examples/gold.json` 里 `label: tic` | 91 | 虚构金标口癖句。有 `before` 的才传给省力改写 |
| `examples/consensus-tic.json` | 32 | 两人同判 tic 的虚构正文。不带 before |

合计 123。正常句、人工不可判定、留出集都不进。

## 怎么滤

离线自查必须是「已修复」：文本变了，再扫没有口癖，完整性为 1。然后还要过这些门：

- 字面保真 ≥ 0.85。句首的「那」被一并拿掉时，Dice 大约 0.889，这种约定内的改写要留下，所以门槛不是 0.9。
- 导出再挡一层完整性函数放行的残句：收在顿号、逗号上，或收在「那种 / 一种 / 少见的 / 还是」上。不改自查和金标用的完整性。
- 原文和改写去空白后相同的对，只留第一次。SFT 再按清洗后的正文去重。

单句又没有前文、检测标成不可判定的（例如「不是茶，也不是酒，而是白开水。」）不会被改写成「是白开水。」，直接不进。词面套话删完会残的，保持原文，标成需模型，也不进。「他开口。」这类留白、省略主语、不补情绪，都沿用现有省力改写，导出不再加字。

## JSONL

偏好对，一行一条。`chosen` 是省力改写后的文本，`rejected` 是含口癖原文。

```json
{"id":"gold:g03","source":"gold","sourceId":"g03","category":"template","rejected":"那不是责备，也不是安慰，而是把话放平。","chosen":"把话放平。","fidelity":0.889,"completeness":1}
```

SFT 只留 chosen 里不含口癖、完整性合格、并且通过上面残句挡板的回复：

```json
{"id":"sft:gold:g01","source":"gold","sourceId":"g01","category":"template","text":"他只是看着她。","completeness":1}
```

没有 `prompt` 字段，也没有场景前文。

## 微调 / 训练实验思路

这一节是岗位调研之后的做法，不是已经做过的实验，也还没有启动训练。

岗位说明第 5 条是「熟悉模型训练基本原理、有模型优化数据生产与系统性评测经验者优先」。要的是懂训练在干什么、会生产优化用的数据、会做系统评测。不要求自己把模型训出来。

所以默认先做一版不训练的对照：手里已有的偏好对，加上评测，和没动过的 base 放在同一批虚构 prompt 上比。大约 3 到 4 天能看完。比完再决定要不要真微调。真微调不是这一步的默认动作。数据仍是上面这批 10² 量级（85 对、79 条清洗回复），只够试点。若以后真要训，评测留出 20% 对，不要把 `examples/holdout-v2.json` 混进训练。

评测不能只看 koupi-detector。三处一起看：

- koupi-detector 报每千字口癖率、字面保真、完整性。口癖率掉了，但保真或完整性掉了，这次就算失败，停，不去改检测规则。
- 近义变体探针走 `semantic/`。同一件事换一种说法，看检测器还会不会打中。只报金标三率，近义漏检会被藏住。
- 她做一轮人工盲评。机器分和人看的不一致时，以盲评记录为准，不回头改金标来迁就分数。

数据默认用自采样、自写的虚构句。DeepSeek API 的输出能不能拿去训练，条款还没查到。核实之前，不把 API 输出当训练数据。

若以后决定真微调，再在不训练对照之上加组，不要倒过来。SFT 只用清洗回复，模型看见的是干净句子，看不见被拒绝的转折。DPO 同时看 chosen 和 rejected，更贴「不要这种口癖」，但在百条以内更不稳，也更容易把闭馆、账本这些虚构用词背下来。两组都要和同一 base、同一温度、同一批 prompt 并排，不和金标三率混着报。

岗位上最大的缺口是三块：归因层、从评测到数据再到模型变化的闭环、一张跨模型口癖率主图。手头的顺序就是按这个缺口排的：先把数据闭环的不训练对照做完，再做横评主图，再做归因。这一节只把第一块的做法说清楚。

风险：样本都是虚构的闭馆、账本、码头句子，真训了容易过拟合这个场景。完整性会把极短的完整句算残，也会放过少数空壳。不要用真实对话补量。

不做什么：现在不在这个仓库里启动训练；核实条款前不用 API 输出训练；不把需模型的原句塞进 chosen；不把留出集 v2 当训练集；不为了刷口癖率去改金标判定；不补情绪标签，不加「他/她」，单句无前文不加「是」。
